# 세이브 기획 확정안 (2026-10-25 수신 — 기획 요청 15~23 답변)

> 기획 원문 그대로. 개발 메모는 맨 끝.

| # | 항목 | 기획 확정안 |
| --- | --- | --- |
| 1 | 영구 사망과 저장 | **파티 전멸 확정 시 해당 회차 종료.** 종료 상태를 즉시 저장하고 이어하기를 비활성화. 이전 자동저장으로 전멸 전 상태를 복구하지 못하게 처리. |
| 2 | 되돌리기 허용 여부 | **일반 플레이에서는 허용하지 않음.** F9 불러오기는 개발용으로만 유지하고 배포 버전에서는 제거. 주사위·기습·전리품은 결과가 확정되면 저장하여 재접속해도 동일하게 유지. |
| 3 | 저장 방식·시점 | **자동저장만 제공.** 이동 완료, 주사위 결과 확정, 이벤트 선택, 구매·아이템 사용, 전투 행동 확정, 보상 획득, 막 클리어 때 저장. 기존 턴 시작 저장도 유지. |
| 4 | 슬롯 수 | **1차 구현은 진행 슬롯 1개.** 여러 회차 동시 진행은 지원하지 않음. 새 게임을 시작하면 기존 회차를 교체. |
| 5 | 전투 중 종료 | **진행 중인 전투의 마지막 확정 상태에서 재개.** 아군·적 HP, 상태 이상, 행동 순서, 사용한 아이템, 확정된 결과를 유지. 종료를 도주로 처리하지 않음. |
| 6 | 새 게임과 기존 저장 | 기존 진행이 있으면 **덮어쓰기 확인창 표시.** "기존 진행 상황이 삭제됩니다. 새 게임을 시작할까요?" → `[취소] [새 게임 시작]`. 새 데이터 저장 성공 후 기존 회차를 교체. |
| 7 | 이어하기 화면 정보 | **막·지역·타일 좌표 / 라운드 / 파티 생존 상태 / 누적 플레이 시간 / 마지막 저장 시각** 표시. 전투 중 저장이면 `전투 진행 중` 추가 표시. |
| 8 | 1막 클리어 후 | 보상 지급과 함께 **'1막 클리어' 상태로 저장 유지.** 현재 버전에 2막이 없으면 결과 화면 후 메인 메뉴로 이동. 이어하기는 클리어 결과 화면으로 연결하고 보상은 중복 지급하지 않음. 추후 같은 회차로 2막에 진입하도록 구성. |
| 9 | 설정 저장 | **볼륨·해상도 등은 진행 데이터와 별도로 저장.** 변경 시 저장하며, 새 게임이나 전멸 이후에도 설정 유지. |

개발에서 가장 중요한 건 **결과를 보여주기 전에 저장을 완료하는 것**이야.

**행동 입력 → 결과 계산 → 변경된 상태와 난수 상태 저장 → 결과·애니메이션 표시**

예를 들어 주사위가 **2**로 결정되면, 그 결과와 이동 가능 횟수를 먼저 저장한 뒤 화면에 보여줘. 이후 게임을 껐다 켜도 **2가 나온 상태**에서 이어져야 해. 전투 공격과 전리품에도 같은 규칙을 적용하면 돼.

전멸은 **회차 종료 기록을 먼저 저장한 뒤 게임오버 화면을 표시**하도록 해줘. 이전 백업을 복구하는 기능이 있다면, 종료된 회차를 다시 살리지 않도록 같은 회차의 종료 기록도 확인해야 해.

36. 누적 플레이 시간: 기본안 — 메인 메뉴·게임 중 메뉴·창이 비활성일 때는 세지 않음

## 세이브 추가 수정안 (2026-10-25 수신, 기획 원문 요약 — 요청 29~31 답변 + 32번 수정)
1. **이번 버전은 1막 클리어까지.** 보스 처치 → 보고 완료 → 보상 지급·클리어 저장 → 결과 화면 → 메인 메뉴. K12(베르사유)는 2막 구현 때 활성화, 이번엔 잠금 + 안내 `2막 베르사유 — 추후 공개`. 클리어 후 이어하기 = 클리어 결과 화면, 보상 재지급 없음. 보스전 요청서 문구는 "보고 후 1막 클리어 및 다음 목적지 베르사유 안내. 실제 진입은 2막 구현 후 지원."으로 통일.
2. **설정 5개 확정**: 전체·음악·효과음 볼륨, 해상도, 전체 화면 + `기본값으로 초기화`. 볼륨은 즉시 반영·별도 파일 저장. 해상도·전체 화면은 적용 후 15초 유지 확인 (확인 = 저장, 취소·시간 초과 = 이전 복구). 초기화도 같은 유지 확인. 새 게임·전멸 뒤에도 유지.
3. **최근 전멸 기록 표시**: `이전 회차 — 1막 런던 · 3라운드 전멸`. 이어하기 비활성. 진행 데이터와 별도로 최근 1건만, 불러오기 불가. 진행 중 회차가 있으면 그 정보 우선. 진행·종료 기록이 모두 없을 때만 `저장된 게임 없음`.
4. **저장 실패(32번 수정)**: 경고 → 진행 일시정지 → 재시도 → 저장 성공 후 재개. (33~36은 이번 수정 범위 아님)
