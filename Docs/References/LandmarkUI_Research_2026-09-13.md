# 지형지물(랜드마크) 정보창 UI 리서치 (2026-09-13)

> 목적: 보드 위 특정 지형지물 오브젝트(성소/감옥/유적 등, 역할이 서로 다른 POI)를 **Ctrl+우클릭**했을 때 뜨는 정보창과, 종류가 다르다는 걸 보여주는 시각적 구분 방식을 정하기 위해 10개 게임/프랜차이즈 사례를 조사했습니다. 모티브 참고용이며 수치·코드·에셋을 그대로 옮기지 않았습니다.

## 조사한 사례

1. **For the King** — 보드 위 상자/이벤트가 "제목 + 설명 텍스트 + 선택지 버튼" 카드 형태로 뜸(예: Lucky's Vault). 우리 정보창의 기본 카드 레이아웃 근거.
2. **Slay the Spire** — 맵 노드는 원래 아이콘 "모양"만으로 구분(전투/휴식/상점 등), 색상 구분은 기본 게임엔 약해서 커뮤니티 모드가 따로 색(엘리트=빨강, 휴식=금색, 상점=초록)을 추가함. → 색상만으로는 부족하고, 모양(또는 배지)까지 같이 써야 한다는 근거.
3. **Heroes of Might & Magic III** — 광산/신전/사원/오벨리스크 등 지형 구조물 종류가 매우 다양하고, 각각 클릭하면 고유한 정보/상호작용 창이 뜸. "지형지물마다 역할이 다르고 각자의 정보창이 있다"는 우리 요구사항과 가장 가까운 선례.
4. **Battle for Wesnoth** — 마을/성채/성 타일이 서로 다른 지형 그래픽을 가짐(에디터에서 오버레이 아이콘으로 위에 추가 표시도 가능). 지금 우리는 3D 오브젝트가 없으니 "타일 색"으로 이걸 대체.
5. **King Arthur: Knight's Tale** — 맵에 신전/캠프파이어/상자 등 POI가 종류별로 표시되고 맵마다 개수 제한이 있음. 파티 기반 그리드 전술 장르로 우리와 가장 가까운 이웃.
6. **Darkest Dungeon** — 커리오(상호작용 오브젝트)가 던전 테마별로 묶여 있고, 상호작용하면 설명 텍스트 + 위험/보상이 뜸. 정보창에 "묘사 문구"를 넣는 톤의 근거.
7. **Divinity: Original Sin 2** — 맵 마커 색이 중요도/카테고리를 나타냄(빨강=핵심 퀘스트, 노랑=참고 정보). 색상을 "종류"가 아니라 "중요도"에 쓰는 대안적 용법도 있다는 참고 사례.
8. **Total War 시리즈** — 캠페인 맵에서 우클릭은 보통 "이동/공격 명령"이지 정보 열람이 아님. → 우리가 **Ctrl+우클릭**으로 "정보 열람 전용" 제스처를 따로 만든 게 장르 관례와 충돌하지 않게 구분해주는 근거(향후 일반 우클릭을 다른 용도로 써도 안전).
9. **Battle Brothers** — 월드맵 로케이션이 민간 정착지/군사 정착지/도적 은신처/전설 로케이션 등으로 명확히 분류되고 성격이 다름. 우리의 "성소/감옥/유적" 같은 카테고리 분류 방식의 근거.
10. **Wildermyth** — 사이트(장소) 종류별로 버튼/깃발 색이 다름(연구=보라, 제작=파랑, 사이트=주황). 카테고리별 고정 색상 컨벤션의 직접적 근거 — 우리도 랜드마크 타입마다 고정 accent color를 씀.

## 적용한 설계 결정

- **색 + 배지(글자) 둘 다 사용**: Slay the Spire 사례(색만으로는 접근성이 떨어짐)에 따라, 아직 아이콘 아트가 없는 지금은 타입별 고유 **accent color** + **1글자 배지 텍스트**(예: "성"/"감"/"유")를 함께 써서 구분. 실제 아이콘 아트가 생기면 배지는 아이콘으로 교체.
- **정보창 레이아웃**: For the King / Darkest Dungeon 식으로 제목 + 카테고리 + 설명 텍스트 + 닫기 버튼의 단순한 카드형 모달.
- **Ctrl+우클릭 제스처 유지**: Total War처럼 우클릭이 "명령"으로 쓰이는 장르 관례가 있어, 일반 우클릭과 겹치지 않도록 Ctrl 조합을 그대로 사용(이미 요청하신 방식과 일치).
- **카테고리는 자유 텍스트, enum 아님**: Heroes III/Battle Brothers처럼 실제 게임에서는 지형지물 종류가 많고 계속 늘어나므로, 지금 3종류로 enum을 고정하지 않고 `LandmarkDefinition.Category`를 문자열로 둬서 나중에 몇 종류가 되든 코드 수정 없이 데이터만 추가하면 되게 함.
